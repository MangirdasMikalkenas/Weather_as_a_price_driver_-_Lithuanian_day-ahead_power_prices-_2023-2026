# Changes that mutmut makes and the tests do not catch

[mutmut](https://github.com/boxed/mutmut) 3.8.0, configured in `setup.cfg`, makes every small change it can in `src/backtests.py`, `src/bank_products.py`, `src/exposure.py` and `src/risk_engines.py` (`+` for `-`, `<` for `<=`, a constant changed by one, an argument dropped, a string altered) and runs the tests of those four modules on each changed copy. Of 1,827 changes, the tests catch 1,721 (94.2%). Each of the other 106 was read; none is an error that a test should catch.

The first run, before tests were added for what it found, caught 1,528 of 1,824 changes (83.8%). The tests added since check, among others, an SA-CCR netting set with trades in all three maturity buckets, collateral, a negative value, the 10-day maturity floor and the parts of its result; the Hull–White bond price and drift against numerical integrals, today's forward rates and the step that each column of normals moves; the coupons of the simulated swap and its value at each reset; every entry of the backtest summary; the Acerbi–Szekely statistic and p-value by hand; the supervisory shocks between maturity 0 and infinity; many scenario curves priced at once; annuity and run-off schedules; and the defaults that the notebooks rely on, such as absolute changes, EPE over one year and a 30-row EWMA warm-up. None of them found an error in the code. One change makes the code more robust: `rolling_scenario_pnl` now starts from missing values instead of uninitialised memory, which had let a skipped chunk of days pass its test by chance.
